# Code smells and refactoring: a review of reviews

**In one sentence:** across 40 literature reviews from 1992 to 2018, smells and refactoring are tied to
maintainability and understandability, but detecting smells is unreliable, so refactoring is best done as a small,
daily habit rather than driven by a detector.

## Claim

Code smells and refactoring are "two faces of the same coin": both bear on understandability, maintainability,
testability, complexity, functionality and reusability. Refactoring affects those quality attributes more directly
than smells do.

## Evidence

- A tertiary review: 40 secondary studies (systematic reviews, mappings and surveys) found in eight databases,
  answering five research questions.
- **Most-studied smells:** Blob and God Class (also called Large Class) among design smells, Duplicated Code among
  code smells.
- **Detection is inconsistent.** There is no consensus on threshold values, different techniques disagree, false
  positives are frequent, and most tools detect only three or four smell types. Manual detection is described as
  slow and error-prone.
- **Refactoring is not always an improvement.** Some refactorings lower quality when applied.
- **Practitioners:** the authors argue refactoring should be a daily habit. Neglected refactoring grows into large
  refactorings that must be planned, interrupt daily work and need justifying to management. Code review helps find
  what to refactor. Primitive refactorings are the most applied because tools automate them.

## Adopted

- **The ratchet, not a fixed threshold** (`CONSTITUTION.md` section 3). Because thresholds are not agreed and
  detectors disagree, the complexity limit records today's violations as a baseline that may only shrink, instead of
  claiming one number is correct for every codebase.

## Not adopted

- Refactoring in small steps as part of normal work, rather than in separate clean-up projects. It is a working
  habit, not a team agreement with a check, so the shared kit leaves it to each person's own setup.
- Smell-detection tools as a gate. The review's own findings (inconsistent results, few smells covered, high false
  positives) argue against blocking merges on them.

## Limits

- Covers literature up to 2018, before LLM coding assistants; nothing here is about generated code.
- Mostly a map of the research field and an agenda (13 open issues), not new measurements.
- Java dominates the tools and experiments the underlying studies used.
- The note's author did not read every section of the 44-page paper; see `read` above.
